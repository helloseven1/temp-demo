# 使用规范（从稿子到成片）

`docs/` 专门放说明文档。看「有哪些零件」去 [`库字典.md`](./库字典.md)；本文件只讲**怎么用**。

---

## 1. 一句话流程

```text
写 output/<id>/spec.json  →  build.py 生成自包含 episode.tsx  →  remotion-demo 的 npx remotion 渲染  →  抽帧核验
```

本项目 `remotion-Pro` 只放三库、生成器、spec 和成片，**不建 Remotion 工程**；
`remotion-demo` 只放 Remotion 工程和依赖，不塞本项目的库。

---

## 2. 目录约定

```text
remotion-Pro/
├── docs/                     说明文档（本目录）
└── 02-generate-video/
    ├── library/              三库共享
    │   ├── styles/           风格
    │   ├── motions/          动效
    │   ├── components/       组件
    │   └── engine.tsx        组装引擎
    ├── build.py              生成器
    └── output/
        └── <id>/             一个片子一个目录，所有东西都在这
            ├── spec.json     稿子（文案 + intent + items）
            ├── episode.tsx   生成物：自包含单文件
            ├── episode.mp4   成片
            ├── audio/        分段配音缓存（可删，会重建）
            └── qa/           抽帧核验图
```

JSON **不要散落到别处**，就放在 `output/<id>/spec.json`。

## 3. 新建一个片子

### 3.1 建目录

```bash
mkdir -p "H:/Multimodal-workspace/remotion-Pro/02-generate-video/output/demo-hello"
```

`id` 用小写英文 + 连字符，建议目录名和 `spec.json` 里的 `id` 完全一致。

### 3.2 写 spec.json

一个最小可跑例子：

```json
{
  "id": "demo-hello",
  "title": "示例片子",
  "brand": "我的栏目",
  "style": "fresh",
  "voice": "zh-CN-XiaoxiaoNeural",
  "rate": "+8%",
  "chapters": [
    { "badge": "1", "name": "开场", "fromSub": 0, "toSub": 3 }
  ],
  "lines": [
    {
      "text": "AI [[不是]]专家。",
      "intent": "hook",
      "items": [
        { "kind": "big", "t": "不是专家", "d": "先别急着下结论", "accent": "blue" }
      ]
    },
    {
      "text": "先说清[[目的]]，再说清[[边界]]。",
      "intent": "steps",
      "items": [
        { "kind": "sticky", "motion": "pop",  "t": "定向", "accent": "amber" },
        { "kind": "sticky", "motion": "drop", "t": "深挖", "accent": "blue" }
      ]
    },
    {
      "text": "这一步最关键。",
      "intent": "conclusion",
      "items": [ { "kind": "stamp", "badge": "记住" } ]
    }
  ]
}
```

写稿时记住三条：

- **一句 = 一页**。`lines` 里一条就是一屏画面，不要自己写 beat、坐标、颜色。
- `[[高亮]]` 只包关键词；配音时括号会被去掉，画面里会变成高亮色。
- `chapters` 用字幕下标：`fromSub` 含、`toSub` 不含。

### 3.3 选组件和动效

查 [`库字典.md`](./库字典.md)：

1. `style` 选 `paper` / `ink` / `fresh` / `whale`；想和拆解视频同一视觉语言，选 `whale`。
2. 每句选一个 `intent`，它给默认布局、默认动效、小标题、错峰。
3. `items[].kind` 选组件；`items[].motion` 选动效。
4. 组件和动效**自由组合**，没有绑定关系。

动效优先级：

```text
items[i].motion  ＞  行级 motion  ＞  intent 默认
```

需要覆盖布局或小标题时，行级加 `"layout": "row"` / `"title": "要点"`；传 `"title": ""` 可隐藏小标题。

### 3.4 用「鲸语」风格包（`style: "whale"`）

这是一套和原片同视觉语言的固定包：米色点阵 + 蓝鲸吉祥物 + 扁平插画 + 三色便签 / 红章 / 天平 / 放大镜。

- 吉祥物**不写进 `items`**，由 Shell 固定在左下角。根级 `mascot` 设默认，行级 `mascot` 改每句气泡和表情：

```json
"mascot": { "t": "鲸鲸!!", "face": "happy" },
"lines": [
  {
    "text": "这是两年前的那一套。",
    "intent": "hook",
    "mascot": { "t": "鲸？", "face": "think" },
    "items": [ { "kind": "big", "t": "过期了" } ]
  }
]
```

- 签名组件当普通 item 用：`trioSticky`（三色便签 + 红章）、`lensBar`（放大镜 + 双进度条）、`illustration`（扁平插画）；天平配 `"motion": "tilt"` 就是倾斜权衡。
- 只有 `whale` 会渲染吉祥物；`paper` / `ink` / `fresh` 仍是原来的鲸鱼小图标，互不影响。

#### 3.4.1 成套组件（`w*` 前缀）

`whale` 有一套**专门设计的组件**，视觉语言统一、覆盖一整期从头到尾，不用再拿老组件拼。直接按顺序选：

| 页面 | kind | 推荐动效 |
|---|---|---|
| 开场钩子 | `wHook` | `shock` |
| 金句观点 | `wQuote` | `typeIn` |
| 三步清单 | `trioSticky` | `pop` |
| 左右对比 | `wVersus` | `flip` |
| 天平权衡 | `wBalance` | `tilt` |
| 清单表格 | `wTable` | `unfold` |
| 数据指标 | `wMetric` | `wobble` |
| 流程链路 | `wFlow` | `unfold` |
| 结尾结论 | `lensBar` | `rise` |

字段见 [`库字典.md`](./库字典.md) 的「whale 成套组件」小节；完整样例是 `output/whale-suite/spec.json`。

注意：这套组件只是"成套可选"，不锁节奏——每句用哪个、几个、配什么动效仍由 spec 决定；只是选 `whale` 时优先用 `w*` 组件，画面才统一成原片那套视觉。

#### 3.4.2 用图片素材当组件（`img`）

组件不一定用代码画，也可以是一张真实图片。用 `img` 组件 + `src` 引用素材名：

```json
{ "kind": "img", "src": "calendar", "t": "定时间", "w": 300, "h": 300, "motion": "pop" }
```

- `src` 写**素材名**（不带扩展名）。`build.py` 会找 `library/assets/**/<src>.png`（共享）或 `output/<id>/assets/<src>.png`（本集私有，优先），支持 png/jpg/webp/svg。
- 现有共享素材：`calendar`（日历）、`clock`（时钟）、`magnifier`（放大镜）、`target`（靶心）、`gear`（齿轮）。新增素材直接把图片丢进 `library/assets/whale/`，不用改代码。
- `w`/`h` 可覆盖默认 240×240；`fit` 控制 contain/cover；`bare:true` 去掉白卡边框只显示图。
- 图片会 base64 内联进 TSX，成片仍自包含。**不要在 spec 里写文件路径**，写素材名即可。
- 图片颜色固定在文件里，不跟风格换色；要换色得重新出图。代码画的组件（如 `illustration`）才会跟着 token 换。

完整样例：`output/whale-images/spec.json`。

## 4. 生成与渲染

### 4.1 只生成 TSX（先检查）

```bash
cd "H:/Multimodal-workspace/remotion-Pro/02-generate-video"
python build.py demo-hello
```

> `python` 已加入用户 PATH，指向带 `edge_tts` 的受管 Python；重开终端后生效。

产物：`output/demo-hello/episode.tsx`。
它是**自包含单文件**：三库代码 + 文案 + 配音 base64 全内联，拷到任何 Remotion 4 工程都能渲染。

### 4.2 生成并渲染成 MP4

```bash
python build.py demo-hello --render
```

产物：`output/demo-hello/episode.mp4`。`build.py` 会自动切到 `../../remotion-demo` 执行 `npx remotion render`。

### 4.3 单独检查 TSX 是否能被 Remotion 识别

```bash
cd "H:/Multimodal-workspace/remotion-demo"
npx remotion compositions ../remotion-Pro/02-generate-video/output/demo-hello/episode.tsx
```

## 5. 修改与重跑

- 改 `spec.json` 或 `library/` 后，**重新跑 `build.py`**。
- 不要手改 `episode.tsx`：它是生成物，下次会被覆盖。
- 配音有缓存，存在 `audio/`；改了文案想换配音，删掉该目录再跑。
- 改了库代码后要连 `--render` 重跑，否则 MP4 还是上一版。

## 6. 审片规范

每次渲染完必须做：

1. 从成片抽帧到 `output/<id>/qa/`，至少看开头、中段、结尾。
2. 检查文字是否落在卡片边框内；长标题用右对齐 / 缩字号 / 加宽卡片解决，**不允许溢出**。
3. 检查小标题是否逐句累积（句末应淡出）。
4. 检查镜头边界是否落在口播换句点，画面和字幕不能错位。
5. 把 MP4 直接放出来给用户看，静帧只作补充证据。

视觉禁令：

- **永久禁用 zoom-through**（画面冲进中心点再放大），也别用纯硬切；镜头切换用 0.4s 交叉溶解，无缩放 / 位移 / 闪白。
- **文字永远不要删除线**；表达否定用颜色 + `✓` / `✕` 前缀（`tick` 组件已按此实现）。
- 描述性文字多条要右端对齐。

## 7. 常见报错

| 报错 | 原因 | 处理 |
|---|---|---|
| `没有这一集: output/<id>/` | 目录没建或 id 写错 | 建 `output/<id>/` 并放 `spec.json` |
| `风格库无此风格` | `style` 不在三库里 | 改成 `paper` / `ink` / `fresh`，或按字典新增风格 |
| `组件库缺片段` | `kind` 拼错 | 查字典，或用别名 `iconChip` / `steps` |
| `动效库缺片段` | `motion` id 拼错或新增没登记 | 查字典；新增动效要同步 `build.py` 的 `MOTION_IDS` |
| `c_card is not defined` | 生成时没把组件库全量内联 | 用当前 `build.py`，不要手动裁剪内联片段 |
| Windows 找不到 `npx` | 直接 subprocess 调 `.cmd` | `build.py` 已用字符串命令 + `shell=True`，不要改回列表形式 |

## 8. 扩展三库

按 [`库字典.md`](./库字典.md) 第 6 节的登记表改。原则是：

- 组件只负责长什么样，动效只负责怎么出场，风格只负责配色和画布——三者互不绑定。
- 每加一个 id，要同时更新库文件、引擎登记表、`build.py` 校验表（动效）和字典。
- 改完必须跑一遍已有样片回归，确认旧片子没坏。
